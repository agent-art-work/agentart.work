# Contribute to discourse

Use a short branch and PR for each meaningful change. The repository's [contribution and publication rules](../../CONTRIBUTING.md) still govern; discourse notes are not automatically Blog articles or website pages.

- Propose a question with a source passage, stable ID, audience and possible challenge.
- Submit evidence with exact public URLs, check dates, access limits and evidence labels. Use the templates; preserve unknown and contradictory outcomes.
- Challenge a rule with the concrete problem, supporting report, proposed change and condition for review. Say whether it changes wording, a platform practice, an interpretation or the shared method.
- Put reusable practices in platform guides and changing community checks in cases. Keep source snapshots immutable and cite their version in reports.
- Commit reports that support decisions, including failures. Keep routine searches, unused drafts, caches and credentials in ignored local work.

Before review, check local links, source accuracy, example labels, both routes, privacy and third-party attribution. Run the root README's offline package checks. The maintainer accepts changes. Use Issues for concrete work and GitHub Discussions for open questions if enabled; summarize accepted lessons in Git.

No license has been selected. Do not add a license or imply permission to reuse third-party material. Version this discourse draft through this repository's commits and changelog; create separate releases only when ownership or release needs justify them.
